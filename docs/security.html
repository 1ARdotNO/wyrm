Security & responsible disclosure

Found something exploitable in wyrm? Report it privately and we'll work a fix and a coordinated disclosure with you. Please don't open a public issue for anything exploitable.

Report a vulnerability

  • Preferred: GitHub's Report a vulnerability (Security → Advisories) — private vulnerability reporting is enabled on the repo.
  • We aim to acknowledge within a few days and to coordinate a fix and disclosure timeline with you.

Include the affected version/commit, a description, reproduction steps, and impact. Proof-of-concept code is welcome — but never test against systems or data you don't own.

Supported versions

wyrm is pre-1.0; only the latest main is supported. Fixes land on main and in the next tagged release.

Scope & handling notes

  • Untrusted models. wyrm parses OTM documents (YAML/JSON) that may come from other repos or contributors. Parsing is memory-safe Rust with no code execution — a malformed model should fail to parse, never escape the parser.
  • Importers invoke external tools. wyrm init shells out to helm, kustomize/kubectl, and reads Terraform/plan sources you point it at. Those tools run their own templating — only run wyrm init on infrastructure sources you trust, as you would helm template or terraform plan.
  • The GUI live-writes the file. wyrm-gui saves every edit back to the .otm.yaml you opened; it touches no other path and makes no network calls.
  • Automated hardening. Dependencies and Actions are monitored by Renovate; every change is gated by CI (fmt, clippy -D warnings, tests, cargo-deny, CodeQL, Trivy, MegaLinter) before merge.

What is not a vulnerability

  • A "missing" threat finding — the rule library is best-effort and intentionally extensible, not a guarantee of completeness. Propose a rule instead.
  • Findings that require an already-compromised host or working tree.

The full policy also lives in SECURITY.md at the repo root.
